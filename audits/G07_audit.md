# G07 Audit — Generated/minified/vendored detection, wired in (v0.12.0)

Goal: one shared detection module (detect.py) for generated /
minified / vendored shapes; scanner flags with evidence; lint
L006/L007 consuming it; opt-in --auto-shrink in export (profile
option + CLI flag) that excludes detected files before the fit
ladder unless an explicit choice says otherwise; explain +
dashboard surfaces. Baseline 334 tests; build brought the suite
to 366 (32 new in tests/test_v12_detect.py).

## Build notes (decisions taken)

- The minified verdict is tokens.looks_minified, imported — the
  same function the calibrated estimator's family_for uses to pick
  the minified-js family. One judgement, two consumers, no clone.
- Evidence is metadata only: generated evidence is the canonical
  marker string from detect.GENERATED_MARKERS (never the file's
  line), vendored path evidence is the segment name, minified
  evidence is line statistics, and the vendored banner evidence is
  the banner's library name token (the banner is a public license
  header — it is the marker itself).
- Auto-shrink eligibility is tracked by mode ORIGIN inside
  exporter.resolve_modes_detailed: only a mode produced by the
  built-in defaults can be auto-excluded. Selections, profile
  modes, caller --mode (CLI default), include-gate exclusions and
  secret-forced exclusions are all explicit/other and never
  rewritten; reasons are popped if --exclude-secrets also claims
  the file, so a manifest never attributes a secret exclusion to
  auto-shrink.
- resolve_modes keeps its old signature and delegates, so lint,
  check-budget and the manifest-parity pin judge the same modes —
  including the profile auto_shrink option when it is on.

## Audit #1 (after build)

### F1 [HIGH] Head-only minified verdict relabels hand-written code
The build ran looks_minified over the first 4KB only. Its
thresholds (longest >= 300, mean line >= 200, size >= 400) are
whole-text statistics, and a head can be unrepresentative when a
file opens with a dense block. Measured on the two real trees
available: exactly one verdict flip head-vs-full, and it is a bad
one — GhostBus src/tools.mjs, hand-written MCP tool definitions
whose opening TOOLS array packs long description strings onto
single lines (head mean 204 chars/line, whole-file mean 125;
looks_minified(full) is False). The scanner flagged it minified
and --auto-shrink excluded a hand-written source file: the exact
failure this goal's conservative bias exists to prevent. Fix:
the minified detector judges the FULL text whenever the caller
has it (the scanner already read the whole file for token
estimation, so this costs no extra I/O); generated markers and
vendored banners stay head-only, since a header/path check is
head-shaped by definition. detect_minified keeps a head-only
fallback for callers that genuinely only hold a head, documented
as the weaker form. After the fix, GhostBus --auto-shrink
excludes only examples/mcp_config.example.json (a genuinely
single-line compact JSON, 158 estimated tokens): ON totals
129,555 -> 45,612 vs OFF 129,555 -> 45,770.

### F2 [MEDIUM] Auto-shrink could exclude a profile entry point
Fit has always refused to auto-exclude entry points, but the
build's auto-shrink only respected explicit MODES. A profile that
names entry_points (an explicit user signal about which files
matter) without also pinning their modes could see a generated
entry point silently excluded. Fix: resolve_modes_detailed skips
auto-shrink for profile entry_points, same protection philosophy
as fit. Pinned by a test.

### F3 [LOW] Scanner imports detect inside _add_file per file
`from .detect import ...` sat inside the per-file helper. Module
imports are cached so the cost is a dict lookup, but every other
scanner dependency is a top-level import and detect.py has no
cycle with scanner.py (it imports tokens only). Moved to the top.

### F4 [REVIEWED, DRIFT INVENTORY] L006/L007 outcomes vs v0.11
L007 now consumes detect_generated. Deltas, all deliberate:
(a) header window 12 -> 15 lines (more hits, the spec's window);
(b) markdown and notebook files no longer fire L007 (prose scope —
a README mentioning a marker is documentation); (c) the marker
list gains thrift's "autogenerated by"; (d) evidence is the
canonical marker under detect's specificity order, so a protoc
header now reports 'code generated' where v0.11 reported
'generated by' (message text only). All v0.11 fixtures keep their
outcomes (41 lint tests pass unmodified); this repo's self-lint
is unchanged at the same 4 justified warns from G6. L006 consumes
detect.line_stats with its own threshold semantics untouched —
L006 is the giant-line rule (any language, full text) and stays
broader than the minified verdict by design; a cross-check test
pins a file where L006 fires and is_minified does not.

### F5 [REVIEWED, SOUND] Evidence strings leak nothing beyond markers
Generated: canonical strings from this module. Vendored path: the
segment name. Minified: numeric line stats. Banner: regex-captured
first token plus optional version from a /*! */ license banner —
the marker itself, length-bounded by the token shapes. No code,
no prose, no secret-shaped material can ride along.

### F6 [REVIEWED, SOUND] Detector cost on large trees
Per file: one 4KB slice, <=15-line marker scan, one stats pass
over <=4KB (minified now stats the full text the scanner already
holds — O(file) it already paid for token estimation), one regex
over <=15 lines. No extra reads anywhere: the scanner passes the
text it decoded in _add_file. GhostBus (42 files) and this repo
scan in the same sub-second range as v0.11 in the build smoke.

## Improve #1 (fixes applied)

- F1: detect_minified judges the full text when provided

  unchanged (129,555 -> 45,770), ON excludes only the compact
  example JSON (129,555 -> 45,612). New regression test pins a

  scanner + detect_all(text=...) path.
- F2: profile entry_points are auto-shrink-protected in
  resolve_modes_detailed; test pins a generated entry point

- F3: detect imports moved to scanner module top.

## Audit #2 (of the build + Improve #1 fixes)

### G1 [REVIEWED, SOUND] Post-F1 verdict agreement is exact
Re-measured after the fix: scanner is_minified now equals the
scoped whole-text looks_minified verdict for every file in
GhostBus (42 files) and this repo — zero mismatches (the F1 flip
set is empty by construction, since the scanner passes the full
text it already read). Flagged sets on real trees are minimal
and factual: GhostBus flags only examples/mcp_config.example.json
(single-line compact JSON); this repo flags only its two compact
prices.json copies (single-line, 857-char lines — the same shapes
G6's self-lint already knew as L006 warns). No hand-written code
is flagged on either tree.

### G2 [REVIEWED, SOUND] No head-only minified consumer remains
grep confirms the only detect consumers are the scanner
(detect_all with full text) and lint (detect_generated + line_stats
for L006/L007 — header/stats checks that are head-shaped by
definition). tokens.looks_minified itself is untouched, so the
estimator's per-text family derivation is exactly as calibrated
in G5; the F1 fix changed which text the DETECTOR judges, not
the shared judgement.

### G3 [REVIEWED, SOUND] Protection interplay after F2
Entry points are now protected in both auto paths (fit's own
rule + auto-shrink's F2 skip) and the two compose: auto-shrink
resolves first, fit then protects profile modes/selections and
floors entry points at interfaces. Caller-default origins (a
--mode run) keep their modes under auto-shrink — the conservative
direction (auto never removes more than the built-in defaults
would have included). estimate_context_tokens inherits profile
auto_shrink through resolve_modes, so check-budget judges the
same selection an export would write; that is the standing
shared-resolution contract, not drift.

### G4 [REVIEWED, SOUND] Manifest + validation surface
mode_reason is additive and per-file; validate_bundle and
bundlediff ignore it (both suites green), watch exports carry it
through build_bundle (pinned by a test), and the secret-forced
exclusion still pops any auto reason so attribution never lies.
